# Release Process

## Overview

Releases are triggered by git tags matching `v*` (e.g., `v0.1.5`). The CI pipeline in `.github/workflows/release.yml` builds binaries for macOS (ARM64 + x86_64), Linux (x86_64), and Windows (x86_64), creates a GitHub Release with auto-generated release notes, and updates the Homebrew tap formula at [RedAtman/homebrew-tap](https://github.com/RedAtman/homebrew-tap).

## Steps

### 1. Bump Version

Update the `version` field in `Cargo.toml`:

```toml
[package]
version = "0.1.5"
```

This version becomes the binary's version string (e.g., `transcriber v0.1.5-0-g<commit>`).

### 2. Commit

```bash
git add Cargo.toml
git commit -m "chore: bump version to 0.1.5"
```

### 3. Tag

Create an annotated tag matching the Cargo.toml version:

```bash
git tag -a v0.1.5 -m "v0.1.5"
```

Use `-a` for an annotated tag (git describe prefers annotated tags).

### 4. Verify Locally (Optional)

```bash
cargo build --release
./target/release/transcriber --version
# Expected: transcriber v0.1.5-0-g<commit>
```

The `-0-` suffix means the tag exactly matches HEAD — no commits since tag. If you see `-dirty`, commit or stash pending changes first.

### 5. Push

```bash
git push origin main
git push origin v0.1.5
```

Pushing the tag triggers CI.

### 6. CI Does the Rest

The release workflow:
- Builds binaries for all platforms (`cargo build --release`)
- Uploads artifacts to a new GitHub Release
- Generates release notes from merged PRs
- Updates the Homebrew formula for `brew install transcriber`

## Version String Format

The binary version is generated by `build.rs`:

| State | Example |
|-------|---------|
| Clean tagged release | `transcriber v0.1.5-0-g<commit>` |
| Between tags (dev build) | `transcriber v0.1.5-3-g<commit>` |
| Uncommitted changes | `transcriber v0.1.5-0-g<commit>-dirty` |
| Not in git repo | `transcriber 0.1.5` |

The version prefix always comes from `Cargo.toml`, not from the git tag name. This ensures the binary version always matches the source.
